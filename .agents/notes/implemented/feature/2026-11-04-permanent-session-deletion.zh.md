# Agent Note: 永久删除 Session

Status: implemented

[English](2026-11-04-permanent-session-deletion.md) | 中文

## Problem

归档隐藏对话但保留日志。用户需要独立操作来移除不需要的历史，并报告哪些关联数据会保留。只删除选中的代际可能暴露前代；其他进程持有父会话时删除子会话，可能破坏活动对话。

## Decision

Session API 删除普通 Session，以及 header 明确携带 `origin: subagent` 的传递后代。普通分叉保持独立，即使历史 header 保留父身份。每个目标先通过访问权限与活动检查，再释放 API 持有的 Agent 句柄。其他运行时所有者会阻止删除。持久化后端在移除任何日志前认领每个目标的写入排他，随后先删除后代再删除父会话，并先删除前代再删除选中的代际。POSIX 在继续之前同步每次移除；Windows 使用操作系统的 unlink 完成语义，因为 Node 无法在那里同步目录。会话目录与 POSIX 锁文件保留，以维持锁身份。

控制器在移除日志后清理 Workspace 成员关系、归档与置顶集合、投影检查点、准备历史及搜索文档。检查点删除等待已开始的写入，防止最终 detach 检查点重新创建缓存。永久删除事件与实时 Session 释放不同，使客户端也能移除冷历史与子智能体历史元数据。进行中的列表请求会在旧基线之上重放删除变更。

缺失的存储身份作为成功的空操作处理。部分失败报告已删除身份；`cleanupSessionIds` 将它们带入重试，但只接受历史已不存在的身份。每个身份单独校验权限。共享附件和项目文件保留，因为其他对话可能引用它们。

本决策取代[存储提案](../../proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.zh.md)中的会话删除部分。该提案仍因独立的存储迁移决策而保持活动。[独立分叉决策](../architecture/2026-10-23-independent-session-forks.zh.md)仍拥有普通分叉的权威说明。

## Alternatives considered

**只删除当前文件。** 拒绝，因为保留的前代可能重新变得可见。

**自动取消正在运行的工作。** 拒绝，因为永久删除与停止工作有不同后果。调用方先停止活动；拒绝后确认框仍然可用。

**随 Session 删除附件。** 拒绝，因为不可变附件会被共享，且没有具备引用感知能力的垃圾回收器来确定独占所有权。

## Consequences

删除不可撤销，需要首先聚焦取消的确认框。整棵会话树的删除不是事务：I/O 失败或崩溃可能留下部分已删除的后代。API 失败报告已知移除和可重试清理；进程崩溃会丢失响应，并可能留下需要操作者维护的孤立派生记录。不会通过已删除身份搜索剩余日志，独立历史保持可读。显式删除独立于格式迁移，不改变 Session 事件 schema 或冻结编解码器代际。

定向持久化测试覆盖两种编码、前代移除、后端实例间的所有权，以及变更前的批量排他。API 测试覆盖后代顺序、独立分叉、活动与权限拒绝和部分清理重试。记录历史驱动的浏览器场景固定确认、取消、选中历史移除及重新加载行为。
